WHAT TOLERANCE IS

A symbiotic compiler
for factories.

A compiler turns source code into something a machine can run. Tolerance turns a plant’s scattered information into an operational model that people and software can both act on, and it traces every fact back to where it came from.

01

The problem

Plants run on fragments.

Manuals in PDFs. Orders in spreadsheets. Machine signals in historians. When something drifts, nobody can quickly see which products it touched, or which action is safe.

02

What it does

Compile. Govern. Verify.

It attaches read-only, builds an evidence-backed model, proposes scoped workflows, and runs approved actions through an independent policy gate in a simulator. Then it measures the result.

03

Why symbiotic

The factory is the host.

Tolerance augments the plant instead of replacing it. The plant supplies context and authority. Tolerance supplies understanding and proposals. Verified outcomes flow back, so both get better.

HOW THE SYMBIOSIS WORKS

Four exchanges.
Nobody gives up control.

  1. Plant → Tolerance Sources and signals, read-only first.
  2. Tolerance → People Findings and proposals, each with its evidence.
  3. People → Tolerance Corrections, approvals and the final say.
  4. Outcomes → Both Measured results become history that improves the next recommendation.

Evidence

Every fact has a source

PDF page, CSV row, JSON path or telemetry sample. Imported observations stay distinct from simulator assumptions and AI proposals.

Authority

The model proposes

An independent policy service decides. Default-deny capabilities, scoped approvals, and no self-approval.

Verification

Success is measured

An execution is not a recovery. Each action needs a persisted event and a measured postcondition before it counts.

Learning

History informs, never grants

Verified outcomes update allowed-action preferences. Memory supplies context, not safety rights.
